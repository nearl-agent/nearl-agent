Overview

NEARL is the safety layer for onchain agents on Robinhood Chain. It helps people and AI agents trade without walking into scams or draining a wallet. It has three parts:

ProductWhat it doesStatus
CheckSafety score for any token before you buy itLive on mainnet
GuardA wallet an agent can use but cannot emptyLive on mainnet and testnet
EarnReward pools that pay while a price stays above a safety lineLive on mainnet (one small pool) and testnet

There is no NEARL token. Anyone selling one is not us.

Connect a wallet

  1. Install a browser wallet such as MetaMask or Rabby.
  2. Click Connect wallet. NEARL lists every wallet it finds in your browser.
  3. Approve the connection in your wallet. NEARL asks your wallet to add Robinhood Chain (or the testnet) if it is missing.
  4. To try testnet features, get free test ETH from a Robinhood Chain Testnet faucet, then press Get 10,000 test USD on the Earn page.

NEARL never sees your private key. Your wallet signs each transaction after you approve it.

Check

Paste a token address on the Check page. NEARL runs these checks in your browser against the public RPC. Nothing is signed or sent.

  • Simulated buy, sell and transfer. NEARL runs a trade on a private copy of the chain (an eth_call with state overrides) through the token's deepest pool, including Uniswap v4 pools with hooks such as Pons launches. A failed sell means a possible honeypot.
  • Taxes. The difference between tokens sent and tokens received.
  • Owner powers. NEARL reads the contract bytecode for mint, blacklist, tax-change, trading switch and transaction-limit functions, and checks whether ownership was renounced.
  • Upgradeability. EIP-1967 proxy slots, which let a team replace the code later.
  • Supply. Share held by the owner and share burned.
  • Liquidity. The deepest Uniswap v3 or v4 pool against ETH, WETH or USDG, in dollars.

How scoring works

Every token starts at 100. Each risk found removes points. The total gives the verdict:

ScoreVerdictMeaning
80–100Looks safeNo known red flags found
55–79Be carefulSome risks; read the findings first
25–54High riskSerious risks found
0–24Do not buyFor example, the sell simulation failed
FindingPoints
Selling blocked (possible honeypot)−100
Buying blocked, or wallet transfers fail−40
Tax above 10%−30
Owner can mint−25
Owner can blacklist wallets−20
No Uniswap pool found−20
Upgradeable code · owner can change tax · owner can pause trading · very low liquidity · owner holds over 20%−15 each
Tax between 2% and 10%−10
Has an owner · low liquidity · owner holds 5–20% · owner can set wallet limits−5 each

If the sell could not be simulated, the score is capped at 70 (Be careful), except for well-known tokens such as USDG and WETH.

A good score is not a guarantee. Automated checks can miss risks. Treat the score as one input.

Guard

Guard is a smart-contract wallet for an AI agent. You (the owner) fund it and set the rules. The agent gets its own key and can only act inside those rules.

  • Daily limit and per-trade limit for each token (or ETH). The daily limit resets every UTC day.
  • Approved recipients: the only addresses the agent can pay.
  • Approved contracts: the only contracts the agent can call, such as a DEX router. Approve routers only, never token contracts.
  • Exact allowances: when the agent calls a router, Guard approves exactly the amount for that call, measures what was really spent, and resets the approval to zero.
  • Withdrawals only go to the owner. Pause stops the agent instantly.
  • Every action emits an event, shown as the Guard's activity log.

Set up a Guard

  1. Open Guard, connect your wallet and enter the agent's wallet address (never your own).
  2. Send test USD to the Guard, set a daily and per-trade limit, and approve recipients or a router.
  3. Give the agent its key. It calls pay(token, to, amount) or execute(target, data, token, maxSpend) on the Guard.

Earn

An Earn pool follows an asset price. When joining closes, the pool records the start price. On each check date:

  • Price at or above the early win line (for example 100% of start): the pool ends early with a reward and your full deposit back.
  • Price above the safety line (for example 70% of start): a reward is paid.
  • Price below the safety line: no reward for that check.

If the price is below the safety line on the final check, your deposit is paid back at the price ratio (final price ÷ start price). All rewards are locked in the contract before the pool opens. If checks stop for 7 days, anyone can trigger an emergency exit that returns every deposit.

On testnet, a keeper runs every three hours to start pools and run due checks, and moves the test price a little each time.

HTTP API

The Check API returns the same result as the Check page.

GET /api/check?token=0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168&net=mainnet
{
  "token": "0x5fc5…1d168",
  "name": "Global Dollar",
  "symbol": "USDG",
  "score": 55,
  "verdict": "Be careful",
  "safeToBuy": true,
  "buyTaxPct": 0,
  "sellTaxPct": 0,
  "liquidityUsd": 17935827,
  "upgradeable": true,
  "owner": "0xcFA0…4C6F",
  "findings": [{ "level": "bad", "title": "Owner can create new tokens (mint)", "detail": "…" }],
  "checkedAt": "2026-11-18T12:00:00.000Z"
}
  • net is mainnet (default) or testnet.
  • safeToBuy is true when the score is 55 or higher.
  • Limit: 20 checks per minute per IP. Over the limit you get HTTP 429 with a Retry-After header.
  • Results are cached for 2 minutes.

MCP server

Agents that support the Model Context Protocol can call NEARL directly. The server is stateless and speaks Streamable HTTP with JSON responses.

{
  "mcpServers": {
    "nearl": { "type": "http", "url": "https://YOUR-NEARL-SITE/mcp" }
  }
}

Tool: nearl_check_token with { "token": "0x…", "network": "mainnet" }. It returns a short text summary plus the full result as structured content. The same rate limit as the API applies.

Stock tokens. The result has a stockToken field. It is { "official": true, "symbol": "TSLA", … } for a token created by Robinhood's StockFactory, { "official": false, "impersonates": "TSLA", "officialAddress": "0x…" } for a token that copies a stock (its ticker together with the company name, or the name alone), { "official": false, "lookalikeOf": "AXON", … } when the ticker is the same and the name is similar, { "official": false, "sameTickerAs": "RUN", … } when only the ticker is the same, and null for anything else. The full list is on Official stock tokens.

Agent skill file

Give your agent the NEARL skill file. It tells the agent to check every token with NEARL before buying, and to skip tokens where safeToBuy is false.

Limits

  • Contracts are not audited by an outside firm yet. They are verified, tested, fuzz-tested and scanned with Slither and Mythril (see Contracts → Security), which lowers the risk but does not remove it. Mainnet features stay small and capped until an audit.
  • Check simulates trades on Uniswap v3 and v4, and on Pons V2 launch curves. Tokens on other launchpads that have no Uniswap pool yet cannot be simulated.
  • Holders, launch snipers, bundle wallets and the creator's other Pons launches are rebuilt from every transfer on chain. For tokens with a long history this takes too long, so that part is skipped and marked as not checked. The API gives it a shorter time budget than the website.
  • The public RPC limits log searches, so Uniswap v4 checks can take 10–20 seconds.
  • Earn on testnet uses a test price feed moved by the keeper, not a real oracle.

FAQ

Does NEARL hold my funds?

No. Check is read-only. Guard and Earn funds sit in public smart contracts. Guard withdrawals only go to the owner.

Why did a token I know is fine get "Be careful"?

Usually because the owner keeps powers such as minting or upgrades, or because the sell could not be simulated. Read the findings; they explain each point.

Is there a NEARL token or airdrop?

No. There is no token and no airdrop.
